A pack is a `.feb`: a zip whose root is `manifest.json` plus the modules it
names. The manifest maps **page ids** to modules — the pack's implementation
of the <a href={path("/docs/core-concepts/contracts")}>host contract</a>.

Authors write a file tree of pages (ids, not URL routes):

```
src/pages/
  +layout.svelte
  harbor/
    +layout.svelte
    home/+page.svelte        → harbor.home
    user/+page.svelte        → harbor.user
    notFound/+page.svelte    → harbor.notFound
```

The id is the directory path with `/` turned into `.`. A sibling `+page.ts`
may `export const id = "harbor.home"` when the folder name should not be the
id. `+layout.svelte` files wrap descendant pages, root-first. Route params
like `[slug]` are not ids — the host owns URLs.

`keelPack` discovers those files, emits a module per id, writes the
manifest, and can zip the `.feb`.

The host loads that artifact as a `FrontendBundle` from a **jar resource**, a
**file**, or an **exploded directory** (dev / watch).

<CodeBlock
  lang="kotlin"
  bw="ktor"
  title="FrontendBundle"
  code={`val harbor = FrontendBundle.fromResource("keel/harbor.feb")
val unpacked = FrontendBundle.fromDirectory(Path.of("pack/dist"))

/>

Asset URLs are per bundle: `/__keel/pack/{bundleId}/…`. Seed `entry` / `css`
are rewritten to that prefix so multiple bundles on one app do not clash.

Pass `contract` (typegen's `keel/1` JSON) so a pack that implements an
unknown id fails the build. A pack may implement a subset; the host walks
the theme chain.

The `.feb` layout, `PageModule`, and `RouterAdapter` are specified under
<a href={path("/docs/implementing/pack-adapter")}>Pack adapter</a>.
