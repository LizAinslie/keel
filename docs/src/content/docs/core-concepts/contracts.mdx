The host registry is the contract. Each entry is a **stable page id**, a
**payload type**, and a **path the host owns**. Packs implement ids. They never
own URLs.

That is the whole library. How many packs you install is a deployment choice.

- **One pack** — you are hosting a web UI. Register the pages, write one
  Svelte (or React) frontend, ship it. Keel glues routes, seeds, and visits.
- **Many packs** — you are hosting an app that authors theme. Publish the
  contract (ids + serializers). Installed themes compile against those types
  and provide the page ids the app expects.

```kotlin
@Serializable
data class BlogHomePage(val featured: List<PostSummary>)

@Serializable
data class BlogListPage(val posts: List<PostSummary>, val page: Int)

@Serializable
data class BlogPostPage(
    val title: String,
    val slug: String,
    val body: String,
    val publishedAt: Instant,
)

pages {
    page<BlogHomePage>("blog.home", "/") { BlogHomePage(posts.featured()) }
    page<BlogListPage>("blog.list", "/posts") { call ->
        BlogListPage(posts.page(call.parameters["page"]?.toIntOrNull() ?: 1))
    }
    page<BlogPostPage>("blog.post", "/p/{slug}") { call ->
        BlogPostPage(posts.bySlug(call.parameters.getOrFail("slug")))
    }
}
```

Typegen walks `@KeelType` / `@KeelAction` (and still accepts a `PageRegistry`)
and emits `.d.ts`. Hosts run Gradle `generateKeelTypes` from the `keel.typegen`
plugin. Theme authors depend on that file — or on a published `blog-contract`
module — not on your running server. Paths are host-only and optional for
pages that are only ever returned from custom Ktor routes. Pack authors never
see paths.

```ts
export interface HomePage { viewer: UserRef | null; feed: FeedItem[] }
export interface HarborPages {
  "harbor.home": HomePage
  "harbor.user": UserPage
  "harbor.notFound": NotFoundPage
}
export type HarborPageId = keyof HarborPages

export interface HarborActions {
  "harbor.setName": { in: SetNameIn; out: SetNameOut }
  "harbor.postMessage": { in: PostMessageIn; out: PostMessageOut }
}
```

The map is named `Pages` by default. Publish this file for theme authors.

A pack declares which ids it implements. A blog theme that omits `blog.list`
is still valid — the host skips it for that id and walks the chain. An app
pack usually implements every id in the registry.

<CodeBlock
  lang="json"
  title="linen/manifest.json"
  code={`{
  "format": "keel/1",
  "id": "linen",
  "version": "1.0.0",
  "framework": "svelte",
  "pages": {
    "blog.home": {
      "module": "pages/home.js"
    },
    "blog.list": {
      "module": "pages/list.js"
    },
    "blog.post": {
      "module": "pages/post.js"
    }
  }
}`}
/>

<Callout title="The contract is Kotlin">
  Authors do not invent page ids. If the app expects `blog.post`, a pack that
  ships `post` or `/p/{slug}` does not match. Typed data is the second half of
  the contract: change `BlogPostPage` and typegen fails the theme at build.
</Callout>
