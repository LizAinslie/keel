Crawlers and share bots **GET the real host URL**. That document is the SEO
unit. A visit (`X-Keel-Visit`) is `pushState` plus JSON — social crawlers do
not run JS.

Set `head` in the loader. `respondPage` writes it into the HTML shell
(`<title>`, description, canonical, `og:*`).

<CodeBlock
  lang="kotlin"
  bw="ktor"
  title="Loader head"
  code={`page<UserPage>("harbor.user", "/u/{id}") {
    val user = Board.user(params.getValue("id"))
        ?: throw PageMissingException(path)
    head(
        "\${user.displayName} — Harbor",
        description = "Messages from \${user.displayName}.",
    )
    UserPage(user = user.toRef(), messages = Board.messagesFor(user.id))
}`}
/>

`PageRequest.head(...)` stores the value on the request. Canonical defaults
to the document URL.

Svelte `<Head>` reads the same `page().head`, so visits stay in sync. Props
override the seed. Extra `<meta>` children are client-only.

<CodePair
  fw="svelte"
  title="pages/harbor/user/+page.svelte"
  ts={`<script lang="ts">
  import { Head, page } from "@kolektiv/keel-svelte"
  import type { UserPage } from "@app/page-types"

  const ctx = page<UserPage>()
</script>

<Head />
<h1>{ctx.data.user.displayName}</h1>`}
  js={`<script>
  import { Head, page } from "@kolektiv/keel-svelte"

  const ctx = page()
</script>

<Head />
<h1>{ctx.data.user.displayName}</h1>`}
/>

A document GET of `/u/{id}` contains the display name in `<title>` **without
executing JavaScript**. That is the test that matters for share bots.

<Callout title="Do not author head in the pack for SEO">
  There is no JS runtime in Ktor. Present <code>seed.head</code>. See
  <a href={path("/docs/core-concepts/seed")}>Seed and headers</a> for the JSON
  shape.
</Callout>
